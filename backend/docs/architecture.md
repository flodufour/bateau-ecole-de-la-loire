# Backend — Architecture

## Overview

The backend is an **ASP.NET Core Web API** (.NET 8). It follows a layered architecture: each layer has one responsibility and only talks to the layer directly below it.

```
HTTP Request
    ↓
Controller       → validates input, calls service, returns HTTP response
    ↓
Service          → business logic (rules, orchestration)
    ↓
Repository       → data access (EF Core queries)
    ↓
PostgreSQL
```

This separation keeps the code easy to test and change. If you swap PostgreSQL for another database one day, only the Repository layer changes.

## Folder structure

```
backend/
├── src/
│   ├── Controllers/     # HTTP endpoints — thin, no business logic
│   ├── Services/        # Business rules and orchestration
│   ├── Repositories/    # EF Core queries, one per entity
│   ├── Models/          # EF Core entities (map to DB tables)
│   ├── DTOs/            # What the API receives and returns (never raw entities)
│   └── Data/
│       ├── AppDbContext.cs      # EF Core entry point
│       └── Migrations/          # Auto-generated DB migrations
├── docs/                # This documentation
├── CHANGELOG.md
└── BateauEcole.Api.csproj
```

## Key concepts

### DTOs (Data Transfer Objects)
The API never exposes EF entities directly. A DTO is a plain object that shapes exactly what comes in and goes out of each endpoint. This prevents leaking internal DB structure and makes the API contract explicit.

### EF Core migrations
Every schema change goes through a migration file generated by `dotnet ef migrations add <Name>`. Never edit a migration after it has been applied — create a new one instead.

### Async everywhere
All I/O operations (DB queries, email sending) are `async/await`. Blocking with `.Result` or `.Wait()` causes deadlocks in ASP.NET — never do it.

---

## Authentication

JWT (JSON Web Tokens). The client receives a token on login and sends it in the `Authorization: Bearer <token>` header on every protected request. The API validates the token on each request without hitting the database.

---

## Error handling

A global exception middleware catches unhandled exceptions and returns consistent JSON error responses. Controllers only return explicit `Ok()`, `BadRequest()`, `NotFound()` etc. — never throw HTTP exceptions manually.
